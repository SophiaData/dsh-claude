# Agent Note: Host 0.2.1-rc.5 adaptation

Status: implemented — package identity and Host peers retargeted; `pnpm check` passes on `adapt/0.2.1-rc.5`.

## Problem

Upstream `@norman-else/dsh-claude` targets the `0.1.7-rc.2` package line. Local DeepSeek Harness Desktop reports CLI `0.2.1-rc.5`. Without adaptation, JobKind registration and package contracts fail against the current Host.

## Decision

- Rename to `@sophiadata/dsh-claude@0.2.0-sophiadata.0`.
- Raise `@deepseek-ai/dsh-*` peers to `>=0.2.1-rc.5` and pin the development graph to `0.2.1-rc.5`, except `@deepseek-ai/dsh-invariants@0.2.0-rc.2` (no `0.2.1-rc.5` on npm).
- Extend `JobKindMap` with `subagent` and `claude` via declaration merging; keep `hostJobKind` mappings unchanged.
- Keep upgrade detection for legacy `@norman-else/dsh-claude` managed preset content.

## Alternatives considered

- Install/smoke only without source changes — rejected; Host API adaptation was required.
- Map former `subagent` jobs onto `claude` only — rejected; merge keeps UI/job semantics.
- Block on a missing `dsh-invariants@0.2.1-rc.5` — rejected; use published `0.2.0-rc.2`.

## Acceptance criteria

- `pnpm run check` exits 0 on this branch; targeted Windows-discovery tests (executable/spawn) pass on the runtime Node and the build exits 0.
- Bundle patch and client ModuleLoader id use `@sophiadata/dsh-claude`.
- Desktop profile links this checkout; `dsh-claude doctor` locates `claude.exe`, reports version `2.1.296` and signed-in auth.
- A Claude preset session runs a real turn with normal output; session-title provider commits a generated title (anchor rule keeps it stable for trivial messages).
- Read-only gate review of `6f0c15c..HEAD` passes (0 blockers; documentation-consistency suggestions recorded as follow-up); a later review flagged the ask side query, which now carries the same guard.
- A model from another DSH provider (`dsh-fe/deepseek-v4-flash`, `magpie/…`) never reaches the CLI: the request header backs it off to `default`, the turn dispatch guards a session that persisted one, and the ask side query sends no `--model` for it.

## Risks

Verified surfaces are the desktop link install, Windows executable discovery, and a minimal Claude turn; full INSTALL.md smoke coverage (approvals, plan review, background jobs, restart resume, worktrees) is not exercised. The Desktop host was not fully restarted before the preset was confirmed (hot-reload path); a cold-start pass after a full restart remains open.

The foreign-model guard keys on a `/` in the id: every Claude Code model id is bare, and DSH shapes another provider's id as `provider/model`. A future CLI that lists a slash-bearing model value would be backed off to the default; `recordClaudeModels` is the place to revisit if that ever happens.
